# Known Issues

Bugs found in real use, with the source location and a suggested fix. Delete an
entry when it ships with a regression test.

---

## Agent replies can come back empty while the model was billed for output

**Found:** 2026-08-12, classifying real Todoist items in the ADHD app
(`~/Developer/adhd-app`). Roughly 1 call in 10 to a working agent returned:

```json
{"response":"","usage":{"input_tokens":1299,"output_tokens":44},"tool_calls":0}
```

44 output tokens generated, empty string delivered. The caller cannot tell this
apart from a legitimately empty answer, so it surfaces downstream as a parse
error on a reply that was never received. Intermittent on identical input, which
makes it read like a flaky network fault rather than dropped content.

### 1. Only `text_delta` reaches the caller; other delta types are discarded

`internal/forge/agent/provider/anthropic/anthropic.go:271` — the
`content_block_delta` switch handles `text_delta` and `input_json_delta` and
nothing else. `thinking_delta` and `signature_delta` fall through silently, as
does any block type Anthropic adds later. The outer `switch event.Type` has no
`default` either, so unrecognized events vanish without a trace.

When a turn's output lands in a block type that is not `text_delta`, the caller
receives nothing while `message_delta` still reports the tokens
(`anthropic.go:308`).

**Fix:** handle `thinking_delta` explicitly — surface it as a distinct
`StreamEvent` type so callers can choose to show or ignore it — and add a
`default` branch that at minimum counts unhandled event types for diagnostics.

### 2. `resp.Content` never carries text, so there is no fallback copy

`anthropic.go:288` — `currentContent` only ever gets `tool_use` blocks appended.
Text exists solely as the side effect of streaming callbacks
(`runtime.go:263-264`), so `resp.Content` has no authoritative copy to fall back
on when the stream handler misses something.

That makes issue 1 unrecoverable rather than merely lossy: there is no second
place to look.

**Fix:** append the accumulated text to `currentContent` at `content_block_stop`,
the same way tool_use blocks are. Then `resp.Content` is complete on its own and
streaming becomes a presentation concern rather than the sole transport.

### 3. Nothing asserts that billed output produced deliverable content

`internal/forge/agent/httpserver/handlers.go:133` builds the reply purely from
`Output.OnText`. No layer checks the obvious invariant: if
`resp.Usage.OutputTokens > 0` and no tool calls were made and the accumulated
text is empty, content was lost.

**Fix:** check that invariant in `runtime.go` after the stream completes and
return an error naming it. A loud failure is recoverable — callers can retry —
whereas an empty string is silently wrong. This is the single highest-value fix
of the three, because it converts every future instance of this bug class into a
diagnosable one.

### Impact on callers

Any consumer parsing structured output has to defend against this itself. Otto
now caps classification retries at three and falls back to a safe default, which
is a workaround for a fault it cannot see the cause of — the client is guessing
because the transport does not distinguish "the model said nothing" from "the
model's answer was dropped".

Suggested regression test: a mock provider that emits a `thinking_delta` and a
`message_delta` carrying `output_tokens`, then asserts the invoke either returns
the content or fails loudly. Neither is true today.

## `agent deploy --target docker` emits artifacts that cannot build

**Found:** 2026-08-10, containerizing the Otto agent for the ADHD app
(`~/Developer/adhd-app`). All four issues below were hit in a single
`trove forge agent deploy otto --target docker --output ./deploy`.

Every one of them is in `internal/forge/agent/deploy/docker.go`.

### 1. Builder image pins Go 1.23, module requires Go 1.25

`docker.go:43` — `FROM golang:1.23-alpine AS builder`

`go.mod` declares `go 1.25.0`, so the build fails immediately on any
`go mod download`. Nothing generated by this target has ever built.

This is also the only hardcoded Go version in `internal/forge/`, so it will
drift again the next time the module's Go version moves.

**Fix:** derive the tag from the module's Go directive at generation time rather
than hardcoding, or at minimum bump to `golang:1.25-alpine` and add a test that
parses `go.mod` and asserts the template matches.

### 2. Runtime stage omits `.trove/forge.yaml`, so the agent is never found

`docker.go:58` — `COPY agents/{{ .AgentName }}/ /app/agents/{{ .AgentName }}/`

`.trove/forge.yaml` marks the workspace root. Without it the container starts,
`agents/otto/agent.yaml` is present and readable at the expected path, and forge
still exits with:

```
✗ Agent not found: otto
Error: agent not found: otto
```

The failure is actively misleading — the agent file is right there, so the error
sends you looking at the agent config instead of the workspace marker.

**Fix:** add `COPY .trove/ /app/.trove/` before the agents copy. Worth also
making the "agent not found" error mention the workspace root it searched.

### 3. Compose references a Dockerfile path that is never generated

`docker.go:96` — `dockerfile: deploy/Dockerfile`

With `--output ./deploy` the files land in `deploy/docker/`, so the actual path
is `deploy/docker/Dockerfile`. Combined with `context: .`, the reference does not
resolve from the workspace root or from `deploy/docker/`.

The printed next steps compound it:

```
cd deploy/docker
docker compose up --build     # fails: cannot locate deploy/Dockerfile
```

**Fix:** make the path relative to the compose file's own directory
(`dockerfile: Dockerfile`), and have the next-steps output run the same command
the test does.

### 4. Template escaping produces malformed compose YAML

`docker.go:102` — `- {{ .APIKeyEnv }}=${"{"}}{{ .APIKeyEnv }}{{"}"}}`

Renders as:

```yaml
- ANTHROPIC_API_KEY=${"{"}}ANTHROPIC_API_KEY}
```

Expected `${ANTHROPIC_API_KEY}`. The `{{"{"}}` escape is mis-typed — the closing
`}}` of the template action lands inside the literal.

**Fix:** `- {{ .APIKeyEnv }}=$${{ .APIKeyEnv }}` in compose (where `$$` escapes
compose interpolation), or build the string in Go and inject it whole. A golden-file
test that parses the generated compose as YAML would have caught this and #3.

### Structural note

Issues 1 and 3 share a root cause: the template is written as if the build context
is the trovery-tools source repo, but the artifacts are emitted into a *user's
agent workspace*, which has no Go module and a different directory layout. Worth
deciding explicitly which context this target is for — building forge from source,
or consuming a released binary — because they want different Dockerfiles.

For reference, the adapted version that does work is at
`~/Developer/adhd-app/agent/Dockerfile`. It resolves #1 and #2, and sidesteps the
context problem with a named build context (`--build-context forge-src=...`).
